# Правка: что взять из чужого поля

Обзор 01.09.2026. Смотрели, есть ли в открытом доступе аналоги библиотеки
и её принципов: панели параметров, агентские скиллы на ту же тему, своды
против генеричности модели. Ниже то, чего у нас нет и что стоит взять,
с обоснованием и с указанием, чего брать не надо.

Вторая спецификация. Первая — `pravka-kontekst.md`, три починки по
контексту величины. Эта от неё не зависит, порядок любой.

## Рамка: что уже снято

Библиотека органов собрана харвестингом, у каждого органа провенанс:

```

nasledovanie / inspektor ← стенд Копинова

```

Экосистема Tweakpane пройдена почти насквозь. Не взяты четыре плагина —
два из них ниже.

Ближайший публичный аналог всей затеи — скилл `tuning-panel` из набора
petekp/agent-skills (46 скиллов, MIT). Философия охвата совпадает почти
дословно, дальше расходимся: там границы ручек агент придумывает каждый
раз («set sensible min/max/step based on the parameter domain»), панель
живёт только в debug-режиме, семантических типов величин нет. То есть
наше объявление — шаг, которого у них нет. Обратно к их подходу не идём.

## A. Экспорт изменённого — для следующего захода модели

**Зачем.** Разрыв в цикле: покрутил ручки → значения легли в localStorage →
в коде остались прежние дефолты → следующая сессия читает старые числа и
рассуждает о ненастроенном стенде. Сейчас это закрывается вручную:
человек смотрит в панель и диктует новые значения.

У petekp это отдельный шаг скилла с прямым обоснованием: «A panel might
expose 100+ parameters. Exporting all values wastes tokens and obscures
what changed. The `default → current` format makes diffs scannable.»

**Почему дёшево.** Отбор уведённых ручек уже написан — кнопка
«Скопировать параметры» в `panel.js` (около 948) перебирает `DEFAULTS`,
сравнивает с `P`, массивы через `JSON.stringify`, и собирает URL.
Нужна вторая форма выдачи того же отбора, не новый механизм.

**Что выдавать.** URL машина читает, человек и модель — нет. Нужен текст
с подписью, типом и парой «было → стало», сгруппированный по секциям:

```
Стенд: gorizont · ~/stendy/gorizont-obyavl.html
Уведено 7 ручек из 79.

Набор
  ttlSize    Титул: кегль      кегль крупный      64 → 78
  mainLead   строка            доля от кегля     140 → 152
Ход
  lag        Инерция           инерция            24 → 41

Впиши эти значения в ZAKON как новые значения по умолчанию.
```

Подписи лежат в `defs`, типы — в `ZAKON` (третий элемент строки), секции —
в `karta.sekciya`. Всё уже под рукой в момент сборки.

**Форма.** Вторая кнопка рядом с «Скопировать параметры», подпись
«Скопировать правки». Обе живут в подвале панели.

**Что не делать.** Не заменять существующую кнопку: URL нужен для
передачи состояния между людьми и для стендов, читающих адрес. Это две
разные задачи с одним отбором.

## B. Палитра формулой вместо списка

**Зачем.** `palitra` сейчас — пресет-список, то есть значения. Это
единственное место библиотеки, где мы держим числа там, где мог бы
стоять закон.

Косинусный градиент (формула Иньиго Килеза, известна с 2015):

```
цвет(t) = a + b · cos( 2π · (c·t + d) )
```

где `a` — середина, `b` — размах, `c` — частота, `d` — фаза; каждый из
четырёх — вектор RGB. Родственные оттенки получаются по построению:
шкала непрерывна, соседние значения не могут разъехаться, любое число
ступеней снимается с одной кривой.

**Почему это наш случай.** Палитра перестаёт быть перечнем и становится
законом с ручками — ровно то, что свод требует от всего остального.
Побочно закрывает вопрос «дай ещё один оттенок между этими двумя»,
который на списке не решается.

**Ручки.** Двенадцать чисел в панели никто крутить не будет. Свернуть до
четырёх, взяв компоненты связанными:

```js
['pal',    'Палитра',   'gradient']     // орган: полоса-превью + четыре ручки под ней
['palA',   'Середина',  'доля', { ot: 'своё' }]
['palB',   'Размах',    'сила'  }]
['palC',   'Частота',   'счёт', { ot0: 0.5, do: 3 }]
['palD',   'Сдвиг',     'доля', { ot: 'своё' }]
```

Плюс список пресетов IQ как отправные точки — они дают шесть готовых
семейств, дальше руками.

**Соседство с существующим.** `palitra` не трогать: списочные палитры
нужны там, где цвета названы (бумага, краска, акцент). Формульная —
для шкал и семейств. Два разных инструмента.

## C. Тип величины «пропорция»

**Зачем.** В TABLICA такого типа нет, и это видно на obtekanie: четыре
ручки `W1, H1, W2, H2` там, где по смыслу две пропорции и один размер.
Правя высоту вслед за шириной, человек каждый раз держит отношение в
голове — ровно та работа, которую тип должен снимать.

**Природа величины.** Безразмерная, ходит вокруг единицы, имеет
осмысленные узлы: 1, √2 ≈ 1.414, 3/2, золотое 1.618, 16/9 ≈ 1.778,
и обратные к ним. Диапазон 0.25…4 покрывает всё, что встречается.

**Особенность, которую нельзя пропустить.** Шаг у пропорции нелинейный:
`shagIzDiapazona` даёт сотую долю диапазона, то есть 0.04 — это грубо
у единицы и бессмысленно точно у четвёрки. Пропорция живёт в
логарифмической шкале: равные шаги должны быть равными отношениями,
а не равными разностями. Либо свой шаг, либо орган со шкалой log.

```js
'пропорция': { organ: 'слайдер', ot0: 0.25, do: 4, edinica: '',
               shkala: 'log', uzly: [0.5, 0.667, 0.75, 1, 1.333, 1.5, 1.618, 1.778, 2] }
```

Узлы — для подтяга рукоятки при подходе близко, как магнит. Проверить,
поддерживает ли слайдер нелинейную шкалу; если нет, это правка органа,
а не только таблицы.

## D. По мере надобности

**Waveform** (Simon Schödler, плагин Tweakpane). Визуализация значений
волной. В diagonal живёт звук — тон, мягкость, серия, громкость — и он
настраивается вслепую: датчик рисует форму закона, но не то, что слышно.
Это нарушение собственного правила «объяви закон и дай датчик». Брать,
когда звук в стендах перестанет быть единичным случаем.

**File Import** (LuchoTurtle) или **Image** (Florian Morel). Загрузка
файла прямо в панель. У «Обтекания» и «Горизонтального лонгрида» в
открытых хвостах стоит «настоящие картинки»; орган снимает цикл
«положить файл → переписать путь → перезагрузить». Брать вместе с
работой над этими двумя стендами, не раньше.

**Profiler** (0b5vr). Несколько величин во времени. Понадобится, когда
в стендах прибавится законов на непрерывных источниках (курсор, время):
они дороги по вычислению, и сейчас цена не измеряется вовсе.

## E. Принципы

**Уровни претензий.** В `de-slop` (тот же набор скиллов) находки делятся
на три сорта, и третий помечен: требует переписывания, а не замены слов.
У нас все претензии равны по весу, и после трёх починок из
`pravka-kontekst.md` их станет заметно больше. Разделить на два сорта:
чинится подстановкой (не названа опора, нет единицы) и требует
переписывания закона (время без кривой, острота без датчика — там
переделывается устройство эффекта). Печатать первыми вторые.

**Порог плотности вместо запрета.** Там же: «плотность длинного тире
выше ~1 на 200 слов» — количественный порог там, где запрет был бы груб.
У нас запреты бинарные, и один уже фактически порог («больше одного
`@media`-перелома без обоснования»). Кандидат на перевод в плотность —
доля пиксельных литералов на стенд: полный запрет неисполним (есть
законные места), а измеримая доля со счётчиком показывает тренд и
попадает в журнал.

**Обязательное против характерного.** В `aesthetic-guide` свойства
эстетики делятся на essential («без этого это не она») и characteristic
(«часто, но не обязательно»). Склад приёмов сейчас этого не различает,
и приём читается как монолит: при переносе непонятно, что можно менять,
а что убьёт приём. Добавить в карточку приёма две строки.

## F. Чего брать не надо

**Debug-only панель.** У petekp прямо: «Tuning panels should never appear
in production», цикл замыкается экспортом значений обратно в код. У нас
панель — часть результата, значения живут в localStorage. Их позиция
противоречит нашей, и заимствовать её нельзя частично.

**Exhaustive как метод.** «Include the parameter — visibility costs
little, missing parameters break flow». Наш П6 определяет охват через
задачу: величины, названные в ней словами. Их путь даёт панели на сотню
ручек, которые сами требуют инструмента навигации.

**Готовые категории параметров.** У них `references/parameter-categories.md`
— плоский список CSS-свойств (padding, flexGrow, zIndex,
gridTemplateColumns) с умозрительными диапазонами. Наши пятнадцать типов
сняты замером с 340 ручек. Это шаг назад по единственной оси, где мы
впереди. Из всего их списка пригодилась одна строка — `aspectRatio`,
она выше как пункт C.
